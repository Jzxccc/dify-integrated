# AI服务注解系统设计文档

## 架构概览
本设计文档描述了AI服务注解系统的架构设计，包括注解定义、Schema生成、服务发现和调用机制。特别关注如何让agent框架更好地调用接入接口。

## 组件设计

### 1. 注解系统 (Annotation System)
- **功能**: 定义用于标记服务和参数的注解
- **实现**:
  - AIService: 标记可由AI调用的服务方法
  - AIParam: 标记服务方法的参数
  - 新增AIServiceAdapter: 为AI模型提供标准化的接口调用方式

### 2. Schema生成器 (Schema Generator)
- **功能**: 根据注解信息生成JSON Schema
- **实现**:
  - 解析方法上的AIService注解
  - 解析参数上的AIParam注解
  - 生成符合JSON Schema规范的描述
  - 支持服务分类和标签，便于agent发现和组织服务

### 3. 服务注册表 (Service Registry)
- **功能**: 扫描、注册和管理AI服务
- **实现**:
  - 启动时扫描所有带AIService注解的方法
  - 存储服务元数据和Schema
  - 提供服务查询接口
  - 支持按功能域、服务类别等维度组织服务

### 4. 服务执行器 (Service Executor)
- **功能**: 执行AI请求的服务调用
- **实现**:
  - 接收AI生成的服务调用请求
  - 验证参数和权限
  - 执行相应的方法调用
  - 提供统一的错误处理和返回格式

### 5. Agent接口适配器 (Agent Interface Adapter)
- **功能**: 为agent框架提供标准化的接口调用方式
- **实现**:
  - 提供服务发现API，让agent了解可用服务
  - 提供统一的服务调用入口
  - 实现服务调用链路追踪，便于调试和监控
  - 支持服务调用结果的结构化返回

## 数据流
1. 开发者在服务方法上使用AIService和AIParam注解
2. 系统启动时扫描并注册这些服务
3. Schema生成器为每个服务生成JSON Schema
4. Agent框架通过服务发现API获取可用服务列表
5. Agent根据Schema理解服务功能和参数要求
6. Agent生成服务调用请求
7. 服务执行器解析并执行请求
8. 结果返回给Agent进行下一步处理

## 安全考虑
- 验证服务调用的权限
- 参数验证和清理
- 防止恶意调用
- 实现服务调用的访问控制和速率限制

## 性能考虑
- Schema缓存机制
- 服务调用的异步处理
- 参数验证的优化
- 服务发现的高效索引
